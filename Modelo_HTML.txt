MODELO MAESTRO - HTML CORPORATIVO INGECART / ING_DIGHUB
=======================================================

OBJETIVO
--------
Crear, actualizar o ampliar paginas HTML corporativas de INGECART / ING_DIGHUB dentro de este repositorio, reutilizando el sistema visual existente y respetando la compatibilidad dual:
- web publicada
- apertura directa en file:///

Este archivo debe servir como guia operativa unica para generar:
- paginas de producto
- informes ejecutivos
- presentaciones continuas
- paginas de servicios
- viewers o landings de video/documentacion cuando aplique

ENTRADAS MINIMAS PARA CREAR O ACTUALIZAR UN HTML
------------------------------------------------
1) Titulo principal.
2) Subtitulo o posicionamiento comercial.
3) Objetivo de la pagina:
   - producto
   - informe
   - presentacion
   - servicio
4) Contenido fuente:

5) Imagen principal y assets complementarios.

REGLAS OBLIGATORIAS DE IMPLEMENTACION
-------------------------------------
1) Crear HTML semantico, limpio y mantenible.
2) Reutilizar css/styles.css siempre que sea posible.
3) No introducir un sistema visual nuevo si la pagina pertenece al ecosistema actual.
4) Mantener compatibilidad con web y file:///.
5) Evitar rutas absolutas de raiz en paginas que deban abrirse fuera del site.
6) Usar rutas relativas correctas segun la carpeta del archivo.
7) Anadir fallback remoto solo cuando ayude realmente a la apertura local.
8) Mantener responsive completo.
9) Mantener alt descriptivo, jerarquia H1/H2/H3 y anclas funcionales.
10) No romper el comportamiento del site principal ni del Media Hub.

RUTAS: REGLA CRITICA DE COMPATIBILIDAD
-------------------------------------
Regla general:
- Si la pagina debe abrir en file:///, evitar href o src que empiecen por / salvo que el archivo solo exista para produccion web.

Convenciones correctas por carpeta:
- En raiz (index.html):
  - css/styles.css
  - assets/images/...
  - soluciones enlazadas con /solutions/... solo si son parte del site servido
- En /solutions:
  - ../css/styles.css
  - ../assets/images/...
  - ../public/videos/... si se enlaza a paginas o archivos publicos
- En /services:
  - ../css/styles.css
  - ../assets/images/...
  - ../documentation/index.html
- En /documentation:
  - ../css/styles.css
  - ../assets/images/...
- En /public/videos:
  - ../../css/styles.css
  - usar mp4 del mismo directorio cuando el archivo publico ya existe ahi

Fallbacks aprobados cuando hacen falta:
- CSS remoto: https://ingesitehub.netlify.app/css/styles.css
- Imagenes remotas: https://ingesitehub.netlify.app/assets/images/...

REGLAS ESPECIFICAS PARA VIDEOS
------------------------------
El Media Hub del home carga videos desde:
- public/videos/videos.json

Cada entrada debe incluir de forma consistente:
- filename
- title
- url
- share_url
- slug
- size
- mtime

Si un video debe ser visible desde el panel de videos del site:
1) El archivo debe existir en public/videos o la URL del JSON debe apuntar a una ruta servida realmente.
2) videos.json debe referenciar la URL correcta.
3) Si existe pagina individual, usar public/videos/<slug>.html
4) La pagina de producto debe enlazar a la pagina individual del video con ruta relativa robusta.

Regla practica:
- Si el mp4 esta en public/videos y la pagina individual tambien, usar src="NOMBRE.mp4" y href="NOMBRE.mp4" dentro de esa pagina.

REGLAS ESPECIFICAS PARA EL BLOQUE PRODUCT SOLUTIONS DEL HOME
------------------------------------------------------------
El bloque de referencia esta en index.html bajo:
- section id="solutions"
- titulo: Product Solutions

Cuando se crea una nueva pagina de producto relevante para el site, normalmente hay que hacer tres cosas:
1) Crear o actualizar el HTML en /solutions.
2) Anadir la tarjeta correspondiente al bloque Product Solutions del home.
3) Si hay video asociado, asegurar presencia en public/videos/videos.json y coherencia con la landing de videos.

Cada tarjeta de Product Solutions debe incluir:
- enlace a /solutions/archivo.html
- thumbnail
- titulo claro
- subtitulo corto orientado a valor industrial

COMPORTAMIENTO CON CONTENIDO VARIABLE
-------------------------------------
1) Si faltan numeros concretos:
- mantener estructura
- no inventar datos
- usar texto cualitativo o TBD solo si es necesario

2) Si hay mucho contenido fuente:
- agrupar en Overview / Features / Specs / Benefits / CTA
- priorizar claridad comercial y legibilidad

3) Si el usuario aporta TXT largos:
- extraer propuesta de valor
- convertir texto plano en bloques orientados a decision industrial
- evitar pegar contenido bruto sin estructura

4) Si hay multiples imagenes:
- usar primero la hero principal
- el resto como apoyo en bloques o consecutivas si el usuario lo pide expresamente

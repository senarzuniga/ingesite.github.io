GUIA MAESTRA - AGENTE DE PROGRAMACION HTML (INGECART / ING_DIGHUB)
====================================================================

OBJETIVO
--------
Crear paginas HTML corporativas (landings e informes ejecutivos) con el estilo INGECART / ING_DIGHUB,
reutilizando el formato ya implantado en este repositorio y adaptando contenidos e imagenes por cliente/proyecto.

ENTRADAS MINIMAS DEL AGENTE
---------------------------
1) Titulo principal del documento.
2) Subtitulo y claim tecnico/comercial.
3) Secciones requeridas (orden y prioridad).
4) KPIs, tablas y datos operativos/financieros.
5) Imagen principal (hero) y assets adicionales (si existen).
6) Bloque de contacto final.
7) Idioma de salida (es/en).

REGLAS DE IMPLEMENTACION (OBLIGATORIAS)
---------------------------------------
1) Generar un unico HTML semantico y limpio por documento.
2) NO embeber CSS de diseno si existe hoja global; reutilizar estilos corporativos existentes.
3) Mantener estructura visual corporativa:
   - Header sticky
   - Hero
   - Tarjetas KPI
   - Tablas premium
   - Bloques callout y conclusion ejecutiva
   - Footer corporativo
4) Mantener compatibilidad dual:
   - Modo web (servido)
   - Modo local file:/// (Edge u otro navegador externo)
5) Evitar rutas absolutas de raiz que rompen en file:/// (por ejemplo /css/... o /assets/...) si se abre aislado.
6) Usar rutas relativas y fallbacks para assets criticos (logo, imagen hero, CSS) cuando aplique.
7) Responsive completo (desktop/tablet/mobile).
8) Print-friendly (A4) para exportacion PDF.
9) Accesibilidad minima:
   - alt en imagenes
   - jerarquia correcta de H1/H2/H3
   - navegacion por anclas funcional
10) No romper estilos globales ni paginas existentes no relacionadas.

REGLA DE RUTAS (CRITICA)
------------------------
- Para documentos dentro de /solutions, usar rutas relativas tipo ../css/... y ../assets/...
- Para documentos dentro de /documentation, usar ../css/... y ../assets/...
- Para documentos dentro de /public/docs, usar ../../css/... y links relativos a archivos del mismo directorio.
- Si se usa JS para cargar docs/assets, detectar mode file:// y resolver URL local alterna.

EJEMPLO DE LOGICA FILE MODE EN JS
---------------------------------
- Detectar: location.protocol === 'file:'
- Si file mode:
  - docs.json -> ruta relativa local
  - enlaces /public/docs/... -> convertir a ../public/docs/... o ruta local equivalente
- Si web mode:
  - mantener URLs publicas del sitio

COMPORTAMIENTO CON IMAGENES
---------------------------
1) Si imagen principal existe, usarla como hero.
2) Si no existe, usar fallback corporativo.
3) No eliminar secciones por falta de imagen.

COMPORTAMIENTO CON CONTENIDO VARIABLE
-------------------------------------
1) Si faltan datos numericos: mantener estructura y marcar TBD.
2) Si sobran secciones: agrupar en
   - Executive
   - Operacion
   - Impacto
   - Conclusion
3) Si tablas son largas: priorizar columnas clave y legibilidad.

4) Menu de anclas funcional.
5) Assets criticos con fallback operativo.
6) Contact y footer presentes.
7) Estilo corporativo consistente.
